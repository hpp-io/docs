# House Party Protocol

Until now, blockchains have been passive infrastructure for recording transactions between people. **House Party Protocol (HPP)** is active infrastructure where agents act and create value on their own.

HPP Mainnet is an AI-native execution layer: a cost-efficient, scalable, and developer-friendly Layer 2 (L2) built on Arbitrum Orbit, secured by Ethereum and enhanced through data availability with AnyTrust DA. On HPP, an agent's onchain execution, inference, and payment complete as one continuous flow.

Through its partnership with [Conduit](https://www.conduit.xyz/) as a Rollup-as-a-Service (RaaS) provider, HPP enables developers to quickly and easily deploy rollup nodes, accelerating the growth of an open and accessible Web3 ecosystem.

## Why HPP?

AI agents have become both suppliers and consumers of services in their own right — yet most infrastructure still assumes a human is in the loop. Payment requires an account and a card, trust depends on reputation, and execution assumes human oversight. HPP closes these three gaps — **payment, trust, and execution** — with one integrated stack.

HPP's technical foundation combines two track records: **Blocko**, which has built enterprise blockchain since 2014 and runs mission-critical, national-scale systems on its Aergo Enterprise platform, and **Aergo**, a public chain in production since 2019. HPP builds on that legacy with infrastructure designed for AI-native, data-centric, and enterprise-ready use cases.

## Three-Layer Architecture

| Layer | Component | Role |
| --- | --- | --- |
| Layer 1 (Security) | Ethereum Mainnet | Final settlement, fraud-proof verification, security anchor |
| Layer 2 (Execution / Settlement) | HPP Mainnet | Agent economy execution and settlement, ETH gas, HPP utility and governance, L3 state anchoring |
| Layer 3 (Application) | [HPPLite](/readme/hpplite) (public) / BESU (enterprise) | Application-specific execution, settling to HPP Mainnet |

A public L3 and an enterprise L3 share one settlement layer, so workloads with different requirements each run in the environment suited to them while sharing transparent auditability on the same public chain.

## The HPP Stack

An agent pays through [x402](/x402), infers through [HPP Router](/hpp-router), connects onchain logic to off-chain compute through [Noösphere](/noosphere), and records its state through [HPPLite](/readme/hpplite). [HPP Hub](/hub) is where applications are built on top, and [Smart Accounts](/smart-accounts) give people and agents a wallet that fits the stack. See the [Ecosystem overview](/ecosystem/overview) for every product.
