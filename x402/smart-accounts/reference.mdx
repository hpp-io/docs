# Smart Accounts: Reference

## Endpoint & network

| | HPP Sepolia | HPP Mainnet |
|---|---|---|
| Chain id | `181228` | `190415` |
| Chain RPC | `https://sepolia-node1.hpp.io` | `https://mainnet-node1.hpp.io` |
| **Bundler + paymaster (one URL)** | **`https://aa-sepolia.hpp.io/rpc`** | not deployed |
| Methods | `eth_*` (ERC-4337), `rundler_*`, `pm_*` (ERC-7677) | — |
| Gas | base fee 0.01 gwei fixed, **priority fee 0** | — |

The endpoint sits behind Cloudflare and is rate-limited per IP (HTTP 429 when exceeded). `debug_*` and any
non-RPC path are not exposed. The SDK uses this URL by default (`HPP_AA_ENDPOINTS[181228]`); pass `bundlerUrl` to override.

## SDK surface (`@hpp-io/aa-sdk`)

| Export | Purpose |
|---|---|
| `createHppAccount({ owner, chain, bundlerUrl?, paymaster?, mode?, salt? })` | User account. `owner` = viem `LocalAccount` or `WalletClient` |
| `HppAccount.ensureReady({ sponsor? })` | One-time setup: 7702 delegation or factory deploy |
| `HppAccount.sendCalls(calls, { setup? })` | One atomic UserOperation. Returns `{ success, txHash, userOpHash, receipt }` |
| `HppAccount.grantSession(spec)` / `revokeSession(id)` / `isSessionEnabled(id)` | Sessions |
| `createHppSessionClient({ account, permissionId, signer, paymaster? })` | Agent side |
| `toEmbeddedOwner({ address, signMessage, signAuthorization? })` | Wrap Privy / Dynamic / KMS signers |
| `RemoteSponsor` | Browser signs, backend broadcasts setup tx |
| `hppSepolia`, `hppMainnet`, `HPP_AA_ENDPOINTS`, `ADDRESSES`, `TOKENS` | Constants |

Source and issues: [github.com/hpp-io/hpp-aa-sdk](https://github.com/hpp-io/hpp-aa-sdk). Example app:
[hpp-io/hpp-aa-examples](https://github.com/hpp-io/hpp-aa-examples) (Privy login → 7702 account → sponsored payment → agent session).

## If you bypass the SDK

Facts you need when talking to the endpoint with raw viem / permissionless:

1. **Fees**: ask `rundler_getUserOperationGasPrice`; generic estimators over-price (priority fee is 0).
2. **`preVerificationGas`**: ~2.5k gas per calldata byte (L1 data). Add a buffer or the op sits in the mempool and is dropped.
3. **EIP-7702**: land the delegation as a separate type-4 transaction. The bundler rejects viem's 2-byte `factory: "0x7702"` marker (it requires 20-byte right-padding).
4. **7702 root signature**: Kernel verifies an **EIP-191 prefixed** userOpHash against `address(this)`. ECDSAValidator (factory accounts) accepts raw or prefixed.
5. **Installing a validator on Kernel**: `initData = hook(20 bytes, sentinel 0x…01) ‖ abi.encode(validatorData, hookData, selectorData)` with `selectorData = 0xe9ae5c53` (`execute(bytes32,bytes)`). Selectors cannot be added later.
6. **Session nonce key**: `[mode 1B][type 1B = 0x01][validator 20B][lane 2B]`. `@rhinestone/module-sdk`'s `encodeValidatorNonce` emits type `0x00` (routes to the root key) — build it yourself.
7. **Factory accounts**: deploying inside the first UserOperation (`initCode`) is rejected because KernelFactory is not staked with the EntryPoint (ERC-7562). Deploy with a normal transaction first.
