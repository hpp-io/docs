# Run an agent

An **agent** is a node that earns fees by serving the compute network: it watches the chain for
requests it can fulfill, runs the matching container, and delivers the result on-chain.

> **Prerequisites:** Node.js ≥ 18, Docker ≥ 20.10, and a small amount of ETH on the target HPP
> network for delivery gas.

## 1. Install

```bash
git clone https://github.com/hpp-io/noosphere-agent-js.git
cd noosphere-agent-js
npm install
```

## 2. Configure

```bash
npm run generate:config     # interactive
cp .env.example .env        # then set KEYSTORE_PASSWORD
```

The generator asks which network to join and which containers to serve, offering the
**community registry** catalog (`hello-world`, `llm`, `freqtrade`, `vrng`, …) — see
[Registry & deployments](./registry-and-deployments.md). It writes `config.json` with the
network's Router/Coordinator addresses filled in. Every block is described in the
[configuration reference](./configuration.md).

## 3. Create your wallet

```bash
npm run init                # prints your agent + receiving addresses
```

This creates an encrypted keystore under `.noosphere/` (unlocked by `KEYSTORE_PASSWORD`):

- **Agent address** — signs delivery transactions. **Fund this with ETH** (delivery gas).
- **Receiving address** — where your earned fees accumulate.

## 4. Run

```bash
npm run agent               # agent API on :4000
npm run dev                 # web dashboard on :3100 (separate terminal)
```

The agent pulls your configured container images and starts serving:

- **Event loop** — WebSocket-first chain monitoring with automatic replay/checkpointing, so
  restarts never miss a request.
- **Scheduler** — for scheduled subscriptions, commits to upcoming intervals automatically.
- **Delivery** — runs the container, submits the output, collects the fee.

### Dashboard

`npm run dev` → http://localhost:3100

| Page | Shows |
| --- | --- |
| `/` | Agent status, containers, verifiers, connection health |
| `/history` | Delivered compute with fees, gas, and profit |

## Levels of participation

| Level | What you run | What it earns |
| --- | --- | --- |
| **Basic worker** | Registry containers (e.g. `hello-world`, `llm`) | Subscription fees for plain deliveries |
| **Verified compute** | A container **plus its proof service**, configured under `verifiers[]` | Fees from subscriptions that require proof-checked results |
| **VRF operator** | The `noosphere-vrng` container + the `vrf` config block | Fees from NoosphereVRF epochs |

## Serving your own container

Anything that speaks the [container contract](./container-contract.md)
(`POST /computation` → `{ output }`) can be served. Add it to `containers[]` in your config;
to make it requestable by *other* consumers, publish it to the
[community registry](./registry-and-deployments.md#contributing-to-the-registry) so it gets a
registry container ID that subscriptions can reference.

## Docker deployment

```bash
npm run docker:build
npm run docker:up          # agent :4000, dashboard :3100
npm run docker:logs
```

The compose file mounts `docker/config.docker.json` and your `.noosphere/` keystore; secrets
come from `.env`. The agent manages model containers through the Docker socket — they run as
siblings, started on demand.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Agent won't start | `.env` has `KEYSTORE_PASSWORD`? Docker running? `config.json` exists? (`npm run init` needs it first) |
| No requests arriving | Agent wallet funded with ETH? Are there active subscriptions for a container you serve? |
| Delivery reverts | Check the agent wallet's gas balance and that your container ID matches the subscription's |
| Container errors | `docker logs noosphere-<container-name>` |
