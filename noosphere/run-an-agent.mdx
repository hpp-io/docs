# Quickstart: run an agent

An **agent** is a node that earns by running compute. This page gets one running from scratch;
[the next page](./sell-compute.mdx) turns it into a paid API with x402.

> **Prerequisites:** Node.js ≥ 18 and Docker ≥ 20.10.

## 1. Install

```bash
git clone https://github.com/hpp-io/noosphere-agent-js.git
cd noosphere-agent-js
npm install
```

## 2. Configure

```bash
npm run generate:config     # interactive — pick containers, opt into selling
cp .env.example .env        # then set KEYSTORE_PASSWORD
```

The generator writes `config.json`: the chain block (RPC + protocol addresses), the containers
your agent can run, and — if you answered *yes* to selling — an `x402Seller` block with paid
routes. Every block is described in the [configuration reference](./configuration.md).

## 3. Create your wallet

```bash
npm run init                # prints your agent + receiving addresses
```

This creates an encrypted keystore under `.noosphere/` (unlocked with `KEYSTORE_PASSWORD`).
Two addresses matter:

- **Agent address** — signs on-chain deliveries. Fund it with ETH **only** if you join the
  on-chain compute network; the x402 rail needs no funds at all.
- **Receiving address** (`PAYMENT_ADDRESS`) — where your earnings go.

## 4. Run

```bash
npm run agent               # agent API on :4000
npm run dev                 # web dashboard on :3100 (separate terminal)
```

The agent pulls your configured container images, starts them as needed, and:

- serves **paid routes** at `POST /paid/compute/<service>` and MCP tools at `/mcp`
  (if selling is enabled) — see [Sell compute](./sell-compute.mdx)
- watches the chain for **compute-network requests** it can serve (if the agent wallet is
  funded) — see [the compute network rail](#the-on-chain-compute-network-rail)

### Dashboard

`npm run dev` → http://localhost:3100

| Page | Shows |
| --- | --- |
| `/` | Agent status, containers, verifiers, connection health |
| `/seller` | Earnings, settle success rate, per-service stats, live paid-jobs feed |
| `/history` | On-chain compute history with fees and profit |

## Docker deployment

Run the whole agent (API + dashboard) in Docker; the agent manages your model containers
through the Docker socket, starting them as siblings automatically:

```bash
npm run docker:build
npm run docker:up          # agent :4000, dashboard :3100
npm run docker:logs
```

The compose file mounts `docker/config.docker.json` as the config and your `.noosphere/`
keystore directory; secrets come from `.env`.

## The on-chain compute network rail

Beyond selling your own models, the agent serves the **on-chain marketplace**: consumers create
subscriptions on-chain, the protocol routes requests, and your agent delivers results back —
earning the subscription's fee per delivery.

```bash
npm run generate:config     # pick registry containers (hello-world, llm, …)
npm run init
# fund the AGENT wallet with ETH (delivery gas) — address shown by init
npm run agent
```

- **Verifiers** — attach proof services for verified compute (higher trust, higher fees).
- **Scheduler** — commits to upcoming subscription intervals automatically.
- **VRF** — optionally serve NoosphereVRF randomness epochs (the `vrf` config block).

> This rail needs ETH for delivery gas. The [x402 seller rail](./sell-compute.mdx) does not —
> an empty wallet can start earning.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Agent won't start | `.env` has `KEYSTORE_PASSWORD`? Docker running? `config.json` exists? (`npm run init` needs it first) |
| Port already in use | Something else on 4000/3100 — set `EXPRESS_PORT` or remap compose ports |
| No compute-network requests | Agent wallet needs ETH, and there must be active subscriptions on-chain |
| Container errors | `docker logs noosphere-<container-name>` |
