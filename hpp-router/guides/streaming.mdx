# Streaming

Set `stream: true` to receive the completion incrementally as **Server-Sent Events (SSE)** instead of waiting for the full response.

```
POST https://router.hpp.io/llm/v1/chat/completions
Content-Type: application/json
Accept: text/event-stream
```

## REST (curl)

### Quota (default)

Omit `X-Payment-Rail` (or leave it unset) to use the prepaid quota rail:

<CodePanel>
<Tabs groupId="streaming-curl-quota" queryString>
<TabItem value="curl" label="curl" default>

```bash showLineNumbers
curl -N -X POST https://router.hpp.io/llm/v1/chat/completions \
  -H "apikey: $HPPROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5",
    "messages": [{ "role": "user", "content": "Stream a short answer." }],
    "stream": true
  }'
```

</TabItem>
</Tabs>
</CodePanel>

### Wallet (`X-Payment-Rail: wallet`)

Include the payment rail header and your API key. For paid models, the first response is typically **`402`** with a `PAYMENT-REQUIRED` challenge — you must sign and retry with `PAYMENT-SIGNATURE` (curl has no built-in signer). Prefer [`@hpprouter/sdk`](../client-sdk/typescript#wallet-x402-payment-rail) for the automatic loop.

<CodePanel>
<Tabs groupId="streaming-curl-wallet" queryString>
<TabItem value="curl" label="curl" default>

```bash showLineNumbers
curl -N -X POST https://router.hpp.io/llm/v1/chat/completions \
  -H "apikey: $HPPROUTER_API_KEY" \
  -H "X-Payment-Rail: wallet" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5",
    "messages": [{ "role": "user", "content": "Stream a short answer." }],
    "stream": true
  }'
```

</TabItem>
</Tabs>
</CodePanel>

The successful response is a stream of `data:` lines, each carrying a partial chunk, terminated by `data: [DONE]`:

```
data: {"choices":[{"delta":{"content":"He"}}]}

data: {"choices":[{"delta":{"content":"llo"}}]}

data: [DONE]
```

## TypeScript SDK

### Quota (default)

<CodePanel>
<Tabs groupId="streaming-typescript" queryString>
<TabItem value="typescript" label="TypeScript SDK (quota)" default>

```ts showLineNumbers
import { HppRouter } from '@hpprouter/sdk';

const client = new HppRouter({
  apiKey: process.env.HPPROUTER_API_KEY!,
  baseURL: 'https://router.hpp.io',
});

const { stream, meta } = await client.chat.stream({
  model: 'openai/gpt-5',
  messages: [{ role: 'user', content: 'Stream a short answer.' }],
});

for await (const event of stream) {
  console.log(event);
}

console.log(meta.resolvedModel);
```

</TabItem>
<TabItem value="typescript-wallet" label="TypeScript SDK (wallet)">

```ts showLineNumbers
import { HppRouter } from '@hpprouter/sdk';
import type { X402PaymentRequired } from '@hpprouter/sdk';

// Implement with @x402/core + @x402/evm (UptoEvmScheme / Permit2).
// Do not set X-Payment-Rail only via defaultHeaders — use paymentRail + paymentSigner
// so the SDK can run the 402 → sign → retry loop.
async function myPaymentSigner(
  paymentRequired: X402PaymentRequired,
): Promise<Record<string, string>> {
  const encoded = await signPayment(paymentRequired); // your signing logic
  return { 'PAYMENT-SIGNATURE': encoded };
}

const client = new HppRouter({
  apiKey: process.env.HPPROUTER_API_KEY!,
  baseURL: 'https://router.hpp.io',
  paymentRail: 'wallet',
  paymentSigner: myPaymentSigner,
});

const { stream, meta, done } = await client.chat.stream({
  model: 'openai/gpt-5',
  messages: [{ role: 'user', content: 'Stream a short answer.' }],
});

for await (const event of stream) {
  process.stdout.write(event.choices?.[0]?.delta?.content ?? '');
}

console.log(meta.resolvedModel);

const finalMeta = await done;
if (finalMeta.x402) {
  console.log('Settled tx:', finalMeta.x402.tx, finalMeta.x402.amount);
}
```

## Streaming and smart routing

Streaming has a special interaction with [`hpprouter/auto`](../smart-routing):

> When `stream: true`, basket classification is **skipped** and the request always uses the configured **streaming fallback** model.

This is intentional — it prioritizes the stability of the SSE pipeline over per-request model selection. If you need fine-grained model selection, send a non-streaming request, or specify an explicit `provider/model` instead of `hpprouter/auto`.

## Usage accounting

Token usage is captured from the streamed response and billed according to the active payment rail (quota or wallet). Because usage logging is asynchronous, it does not add latency to the stream. On the wallet rail, settle metadata may also appear in the stream after content ends — the TypeScript SDK surfaces it on `done`.

## Tips

- Use the `-N` flag with curl (no buffering) to see chunks as they arrive.
- Pass `stream_options` to forward provider-specific streaming options.
- Very large or long-running streams are best consumed from a backend or the Playground rather than an interactive API explorer.
